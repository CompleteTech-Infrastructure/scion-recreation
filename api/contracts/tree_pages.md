# Derived tree pages v1

Status: FND-TREE-CONTRACT attempt-1 author candidate; no implementation, acceptance, or runtime claim. This is an original design. The accepted `canonical.md` and `security.md` remain authoritative. Canonical v1 has **only kinds 01 and 02**. A derived page is neither a canonical object nor a blob containing a disguised tree. All numbers below are format/design limits, not measured capacity.

## Identity and bytes

Integers are unsigned fixed-width big-endian; lengths count bytes. Concatenation has no alignment, padding, varints, optional defaults, extensions, or trailing data. SHA-256 means the complete 32-byte FIPS 180-4 digest, without truncation. Hex text is lowercase ASCII. The separate types and domains are:

```text
magic = 43414e4f5059005452454500                 # CANOPY\0TREE\0, 12 bytes
frame = magic || U16(1) || U8(1) || U32(len(payload)) || payload
digest = SHA256(frame)                         # all 19 header bytes AND payload
DerivedPageId = 43545000 || U16(1) || U8(1) || digest  # CTP\0, exactly 39 bytes
text = canopy-tree:1:01:<64 lowercase hex digest characters>
payload = U16(len(label)) || label || terminal || U16(child_count) || children
terminal = U8(0) | U8(1) || BlobTID | U8(2) || BlobTID
         | U8(3) || BlobTID | U8(4) || DerivedPageId
children = (U8(edge_byte) || DerivedPageId) repeated child_count times
```

Derived version `0001`, page kind `01` (directory radix node), terminal tags `00` absent, `01` regular (100644 octal), `02` executable (100755), `03` symlink (120000), `04` directory are the complete registries. The three file targets are exactly canonical `000101 || digest` (35 bytes). A directory terminal points to another directory's radix root; a radix child points to a continuation of the **same** component map. These two edge roles are never interchangeable. Symlink blobs contain uninterpreted link bytes; traversal does not follow them. There is no deletion terminal, explicit empty directory, timestamp, ACL, count summary, parent, or repository field in a page.

Text parsing accepts exactly `^canopy-tree:1:01:[0-9a-f]{64}$`; binary parsing accepts exactly the 39 bytes above. Reject uppercase, whitespace, alternate spellings, unknown version/kind, wrong magic, canonical TIDs passed as page IDs, and page IDs passed as any canonical TID. Embedded IDs undergo the same type checks. Compare full typed IDs, never digest alone. A frame's type/version/digest must match its expected ID. No future or reserved tag is accepted as v1. Compression, durable envelopes, and RPC serialization are outside the preimage.

## Logical map and unique shape

A repository tree maps canonical full-path bytes to `(file tag, BlobTID)`; no tracked leaf may be an ancestor of another at a slash component boundary. This is the canonical meaning of a prefix-free final tree, not a ban on raw byte prefixes. Each directory represents a map from a **single component** to a file target or a derived directory root. Components are 1..65,535 bytes, contain neither `00` nor `2f`, and are not exactly `2e` or `2e2e`. Paths have 1..65,535 bytes and at most 1,024 components, separated only by `2f`. No host filename cap, UTF-8 conversion, Unicode normalization, case folding, percent decoding, or backslash conversion is permitted. Compare unsigned bytes lexicographically, shorter exact prefix first. Thus `a` and `ab` coexist; `a` and `a/b` cannot both be tracked files. `ff`, `5c`, `41`, `61`, NFC and NFD remain distinct.

Duplicate component keys or duplicate full paths are invalid even if targets agree. An explicit replacement operation changes one existing key; it is not a duplicate input entry. Implicit directories contain at least one tracked descendant. No directory target may be the empty root. Directory depth and all concatenated full paths must satisfy the canonical limits, including when independently valid pages are linked together.

Define `Build(S,d)` on a nonempty map of residual component suffixes, initially the complete directory map with `d=0`. `d` is the number of component bytes consumed before this node, **not** directory depth. Empty residual suffix is allowed internally and is distinct from an empty component. The following definition is normative; it defines bytes, not a required bulk-rebuild implementation:

1. Find the longest common prefix of all keys in `S`, including an empty suffix if present. Let `cap(d)=255-(d mod 256)`. `label` is the first `min(LCP length,cap(d))` bytes. Strip that label from every key.
2. If an empty suffix remains, its target is the terminal. Otherwise terminal is absent. Group every nonempty remainder by its next unsigned byte `b`, remove that byte, and recursively build that group at `d+len(label)+1`.
3. Emit child rows in strictly increasing `b` order. Hash children first, then serialize/hash this node. Directory targets are independently built at `d=0` before their containing terminal.

Empty directory map has the single special root below. Continuations may not denote an empty map (no terminal and no children). Root compression follows the same rule: no artificial permanent empty-label root. In a nonempty node, zero children requires a terminal; an absent terminal with one child requires `len(label)=cap(d)`; with at least two children the label is their maximal common prefix. Every node has `len(label)<=cap(d)`. At `d mod 256=255`, `cap(d)=0`: a zero-label unary node is valid and required when its residual key is nonempty. For example `a*254 || xy` and `a*254 || zw` create such children after the first divergent byte. These rules prevent alternate spellings of the same map. A terminal and children coexist for component-prefix keys such as `a` and `ab`. At a `d=0` root, an empty label cannot have a terminal because that would denote an empty component.

Fragment endpoints are anchored at component offsets 255, 511, 767, ...; the intervening edge byte consumes the next byte. They do not restart at each branch. Thus splitting before an endpoint or merging a removed branch cannot rephase all later fragments. A single component of length `L` takes `floor(L/256)+1` nodes: 255 takes one, 256 two, and 65,535 takes 256. Arbitrary branching can need more nodes, but never more than `L+1` on one component lookup. No recursion through the language call stack is required or allowed to escape these bounds.

## Empty root and strict validation

The only empty map representation is label length zero, absent terminal, child count zero. Its complete frame, digest, literal text ID, and binary ID hex (in that order) are:

```text
43414e4f5059005452454500000101000000050000000000
120fd69aec6d6bc30c93019e2849ab05d1245e26985f70fc07ee6daa41ae4028
canopy-tree:1:01:120fd69aec6d6bc30c93019e2849ab05d1245e26985f70fc07ee6daa41ae4028
43545000000101120fd69aec6d6bc30c93019e2849ab05d1245e26985f70fc07ee6daa41ae4028
```

It is valid only as an entire empty repository/directory-map result, never as a radix continuation or as a directory terminal in a repository tree. Deleting the last tracked leaf returns this root; all now-empty non-root directories are pruned.

Maximum fanout is **254**, excluding edge bytes `00` and `2f`; maximal label is **255 bytes**; maximal complete page is **10,478 bytes**: `19+2+255+1+39+2+254*(1+39)`. The 39-byte terminal size is the directory case. The largest file-terminal page is four bytes smaller. Enforce the byte cap before allocation, then the declared length and every count against remaining bytes using checked arithmetic. An advertised U32 maximum is an error, not an allocation request. All label bytes also exclude `00` and `2f`.

Reject short frames/fields, wrong lengths, unknown tags, inappropriate target kinds, extra targets, trailing bytes, duplicate/unsorted/forbidden edges, too many children, overlong labels, nonmaximal compression, invalid terminal paths, empty child/directory targets, cycles, and cross-version links. A valid digest does not make malformed bytes valid. Validate contextual rules with `(component prefix,d,directory prefix,component count)`; standalone syntax validation is not graph validation. Before following an edge, check the new offset, full-path byte total and component count with checked arithmetic; an overrun fails before fetching/allocating the next node. Graph ingestion must reconstruct/check every represented component and full path, the anchored compression rule and referent roles. A page shared at different contexts must be valid in **each** context. Missing children are incomplete input; a completed mapping with a missing child is corrupt. Disagreement between bytes and an already occupied ID is corruption; never overwrite it.

## Persistent updates and work

Canonical changesets remain simultaneous deltas against parent zero (or the empty tree), not a tree union with other parents. Validate all operation paths and duplicate/order constraints, remove every exact DELETE first, then apply the SETs, and validate the final prefix-free leaf map. Removing a directory path is an absent-leaf no-op; deleting a file does not remove descendants implicitly. SET replaces an exact tracked leaf but may not silently remove conflicting descendants or a file ancestor. Intermediate draft states are private and unpublished. An equivalent overlay implementation must produce the same final map.

Perform each component edit along its search path, copying only changed nodes and directory ancestors. For insertion, split at the first label mismatch or terminal-prefix boundary. Preserve the common prefix, put each divergent byte in its child edge, and retain the respective suffixes; normalize using the **absolute** `d` at each new node. At a matching component replace/create its terminal. Construct a missing suffix with fragments ending at the anchored endpoints above. Existing identical terminals and absent deletes reuse the original ID.

For deletion, clear only the exact terminal. Remove empty continuation nodes. If a node has no terminal and one child, concatenate its label, the child edge and child label, pulling further unary material only until a terminal, branch, or the next anchored endpoint. Re-emit at `cap(d)`, retaining the continuation after that endpoint. If a formerly split label fits, merge it; if it exceeds the cap, fragment it by the same Build rule. Normalize every copied ancestor, including the root; do not retain a unary short root. After a directory becomes empty, remove its directory terminal in its parent and repeat upwards. Never change a file target into a directory target merely by retagging its ID.

Equal leaf maps have identical encoded pages and roots: the component partition, LCP, anchored split, terminal, and child order are functions only of the map. Induction on remaining component bytes and directory height proves uniqueness. The converse, using root equality as content equality, relies on SHA-256 collision resistance. Deletion/reinsertion and different insertion permutations cannot select a different shape. This is not fixed sorted grouping: inserting an early sibling never shifts all later page groups.

The following are conservative analytical per-operation ceilings, not benchmarks. Let `P` be the operation's full path byte length, `C` its component count, `F=10478`, and `B=4*(P+1)+514*C+16`. A successful lookup visits at most `P+1<=65536` pages across all component maps: each descent consumes one byte, and the `C` root visits replace the `C-1` slash bytes. An empty-root lookup visits one. Charge old/new search and copy work four nodes per consumed byte/root. In a directory, deleting a branch can pull at most 256 byte-consuming nodes to the next anchored endpoint plus one terminal endpoint page; beyond it the old continuation is reused. Charging both split and merge 257 nodes per touched component gives at most `B` own-page inspections and produced pages, including root/prune work. Directory-only ancestors are included in `C`; unrelated directory subtrees are not traversed.

Each produced page has at most 255 page references (254 children plus one directory terminal). Starting from the proven retained base graph, re-fetching/rehashing these direct referents without a byte-recheck receipt adds at most `255*B` page operations. Thus page fetch/decode/hash calls each have ceiling `256*B`, immutable page writes `B`, fetched/decoded/hashed page bytes each `F*256*B`, written page bytes `F*B`, and label comparisons plus child-slot inspections at most `509*256*B`. SHA-256 handles at most `164*256*B` page compression blocks including padding. These counts allow repeated reads and do not assume an unbounded cache. A missing transitive validity/retention proof requires full graph validation, not this bounded-update fast path.

File blobs are separate: validate each SET's exact canonical blob target using a durable typed receipt or a streamed full canonical rehash. Let `V` be the sum of those canonical frame lengths, including any repeated rechecks; reserve `V` additional read/hash bytes and their SHA-256 blocks. One such frame is at most `2^40+22` bytes; no page-size bound limits blobs. Unchanged targets inherit the proven retained base graph's validity. For `q` operations sum their `B`s and `V`s, checking every multiplication/addition before admission. These bounds exclude canonical ancestor reconstruction and full initial graph validation: those have separate explicit logical-entry, expanded-reference, page and byte budgets and must never masquerade as one-path updates.

Use an explicit work stack of at most 65,536 frames for a path/context traversal, page-sized buffers, bounded queues, and a configured bounded cache. Before work, reserve checked page/byte/step budgets; stop with resource-exhausted/pending on exhaustion, never publish a partial root or silently drop valid long names. Continuations are private, source/version-bound work state. Every build/import/full-graph-validation/projection work quantum is limited to **4,096 expanded page-context visits**, **4,096 terminal entries**, **42,917,888 page bytes** (`4096*F`), and **1,048,576 blob validation bytes**. Charge every blob byte read/hashed, including existing-blob rechecks. Repeated/shared-page contexts and cache hits still consume visit/entry work. Count the next action before executing it; suspend before any bound is exceeded. A private checkpoint may resume further quanta; total charged work must also fit the admitted job budget. Thus a large valid graph is resumable, not invalidated by a per-quantum cap. Full validation must charge expanded references and logical entries, not just distinct hashes, and cannot publish completion until every reachable context is checked.

An authorized response has at most **256 visible entries** and **1,048,576 encoded projection-payload bytes** (transport/grant overhead is separately bounded). Stop before the next complete entry would exceed either limit; a valid single name fits, and any future projection schema must preserve that property. Paginate the already authorized visible snapshot, never raw page chunks. No hidden scan count, empty filtered gap or continuation position may become a response signal; private work exhaustion cannot be exposed in an existence-dependent way. A page boundary is not a public pagination boundary. Actual implementations must expose the internal counters and substantiate tighter practical budgets and storage latency in IDX-03.

## Durable pages and mapping state machine

The internal mapping key is `(repository_id[16], canonical-v1 kind-02 source_changeset_TID, index_kind=TREE, algorithm_version=1)`. Its storage key encoding belongs to the metadata contract; all four typed values must participate. Changeset identity and repository must match authoritative publication. The required parent-zero tree input must be complete at the declared algorithm version; additional parents establish ancestry and are not tree-merge inputs. A root changeset starts from the literal empty root. A version upgrade uses a new key and cannot rewrite canonical history.

Validate/hash each referenced child/target before writing its parent. An immutable durable receipt may replace re-fetching already validated bytes only if bound to the exact typed ID, referent role, necessary context and retained storage generation. This is bounded metadata, not an authorization grant. Start from a fully validated retained base graph; changed-path checks preserve untouched subtrees. Importing an arbitrary graph requires full bounded graph validation first. File target receipts require the canonical blob type/digest and durable publication. Storage loss invalidates receipts.

Write pages bottom-up with compare-if-absent. Absent ID: install complete validated bytes atomically and durably. Present ID: validate/hash existing bytes, require exact equality, then reuse; partial, unreadable or different content is corrupt, never overwrite permission. Do not acknowledge a parent as durable before its references are durable. Pin the entire reused/new reachable closure against collection while preparing and publishing; transfer the retention pin atomically with mapping visibility. Storage adapters must later define/fsync and test their durability primitive and crash ordering. Failed builds can leave unreachable pages for separately coordinated collection, never dangling published roots.

| Internal state | Meaning / permitted transitions |
|---|---|
| MISSING | No result or work record. May conditionally create IN_PROGRESS. It is not empty. |
| IN_PROGRESS | Versioned, expiring worker token and private progress; no readable root. A fenced retry may resume/recompute after expiry. Concurrent deterministic computation is allowed. |
| COMPLETE(root) | Visible only after all reachable pages/blobs are verified durable and retained. Root must be nonempty. Immutable result. |
| COMPLETE_EMPTY(empty ID) | Same durability rules, literal empty root above. Successful empty tree, not a cache miss. |
| NEGATIVE(reason) | Explicit immutable deterministic non-result for this exact input/version (for example invalid authoritative input). No root. Never use for a timeout, resource exhaustion, missing dependency, denial, or temporary storage failure. |
| CORRUPT(evidence) | Quarantined inconsistent result/storage; no success reads. Repair is a separately versioned/fenced operation preserving evidence. |

Finalize by per-key compare-if-absent on the terminal result slot (a current IN_PROGRESS token is separately fenced). Equal completed results join successfully; a different root, empty/nonempty disagreement, or negative/success disagreement for the same key is corruption/nondeterminism. Preserve both candidates in protected evidence and quarantine the mapping. An expired worker cannot change newer work state; it may submit a fully validated deterministic candidate to the same result comparison. Negative reasons must be stable bounded codes, not worker diagnostics. Storage uncertainty returns unavailable, never MISSING or NEGATIVE. Readers see a single committed terminal state, never a root pointer from IN_PROGRESS. No global lock, global ingestion sequence, repository-wide writer lock, or ref mutation is required. A database's short atomic conditional write is not a claim of formal lock-freedom.

## Authorization and projections

Raw page frames, IDs, child links and internal mapping states remain service-internal, including local cache files and daemon APIs. Raw cache files are private to the service account, never directly mapped into untrusted workspaces. Authenticate socket peers and isolate same-UID jobs with protected per-job credentials or an equivalent sandbox; caller-supplied UID/PID is not identity. Digest possession never grants access. Apply accepted security-v1 authentication, exact scope, path-backed blob grants, current policy freshness, audience, principal and session binding to **every** delivery, including hits, snapshots, streams, resumes and local sockets. Denied or unproven requests must not probe cache/snapshot presence. Internal physical deduplication cannot share authorization decisions. A failed cache tier must not bypass to overload authority.

Selection is a tagged union `ROOT` or `PATH(raw_nonempty_canonical_path)`. For internal binding its exact bytes are `00` for ROOT or `01 || U32(path_length) || path` for PATH. Empty PATH, unknown tags, invalid paths and trailing bytes reject; ROOT is never inferred from empty bytes. PATH selects that exact file or directory, not byte-prefix siblings. A selected directory's descendants use component-prefix semantics. Listing/traversal rights and separately authorized metadata decide what is visible; a known path does not confer rights.

A separately identified authorized projection must bind **repository, source revision, effective view, policy version, exact tagged selection, projection algorithm/version and the exact visible projected content**. The binding is immutable and changes if any member changes, even when visible bytes remain equal. Use the authority-issued opaque projection identity defined by security-v1; never return a raw page digest or use `DerivedPageId`/canonical TID for it. The source identity remains internal if disclosing it is unauthorized. A changed policy/effective view requires reauthorization and a new binding. Concrete projection payload/token/grant encoding is the separate FND-PROJECTION-CONTRACT gate; this document does not invent an incompatible public protocol or claim that gate complete.

Keep that exact semantic binding private when any bound member is hidden. Public projection IDs/cursors must be opaque randomized authority aliases scoped to the authorized session/view and snapshot, without stable equality across new requests; rotate aliases even for identical private bindings. Otherwise a deterministic hash changing on a hidden-only revision would leak a hidden-change signal. An alias never retargets to another binding. Internal cache identity may remain stable, but must not surface through aliases, timing or cache-hit indicators. A cursor continues only its original authorized snapshot and still rechecks current policy; it does not mint a new snapshot or extend freshness.

Generate/paginate from the authorized visible result, with unsigned raw-byte order and a cursor bound to projection identity, policy, selection, response size and visible position. Child references are separately authorized opaque child projections/proofs. No hidden names, raw page/child IDs, omitted counts, raw boundaries/cursors, parent metadata, hidden ancestors, or existence signals may reach a restricted reader. Normalize denied/missing responses, filter before counts/ranking/pagination, and fail closed if timing/work isolation cannot be established. No raw fallback on errors. Proofs, logs, metrics and local multi-user caches observe the same protected boundary.

Owner ADR-007 approves a **30-second maximum revocation design target** after authority revocation commit, superseding the accepted document's older pending-owner wording. Grant and freshness expiry, bounded clock error charged against that bound, and fail-closed uncertainty apply to all deliveries. Cache hits, open handles and resume cannot extend expiry. This artifact establishes no runtime enforcement, constant-time behavior, cloud behavior, or revocation measurement.

## Evidence and remaining gates

`tests/fixtures/tree_pages_v1.json` is the literal conformance corpus: frames and expected hashes/IDs, invalid frames, component/path boundary inputs, and edit histories. Evidence source/inputs and actual command outputs live outside the product tree in `evidence/FND-TREE-CONTRACT/attempt-1/`. A finite reference compiler and independent literal decoder/hash check exercise this design; neither is product runtime code. Reject fixtures with a valid hash still require rejection. Hash checking alone does not establish canonical shape or authorization.

The fixture's `pages` array is a deduplicated table of complete literal frame hex, SHA-256, binary ID hex and text ID. Each positive vector supplies raw `path_hex`/mode/blob-payload inputs and a root plus its reachable `page_ids`. History checkpoint IDs resolve through the same table. Negative frame rows carry the hash of the actual malformed bytes, a claimed ID, and optional explicit context/graph; that hash is not a validity assertion. ID rejection rows specify the target parser through `parse_as` where needed, so a valid derived ID tested as a canonical TID must still reject. Selection rows carry literal tagged bytes. Fixture expectations are assertions to check, never instructions to normalize malformed input.

IDX-03 page/update implementation, durable real storage/crash/GC races, actual protected projection/grant/daemon delivery, resource counters, wide/deep real-backend workloads, cloud and scale proof remain later gates. This candidate requires two independent future reviews (including core specialty), integration of the reviewed SHA, and criterion-level verification at the integration SHA. Authoring and author-support checks are not approval.
