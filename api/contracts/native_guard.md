# Native current-policy guard (internal v1)

`Store.MetadataScope` derives raw principal-index and signed-session selectors from the store-owned authenticated context. The caller supplies the expected policy version. Selectors and operation intents are not credentials. `RecheckCurrent` requires that exact context, scope, immutable typed intent and a caller-owned root PostgreSQL transaction on the pinned database, catalog and serving role. It checks a writable READ COMMITTED transaction, bounded timeouts and synchronous local durability, then acquires shared policy HEAD, credential and session fences in that order. Signed identity claims, signed session proof and enrolled current state are compared before compiling the current policy. Status and lookup require metadata-read; publication requires write. Further repository and path checks are explicit and deny by default.

The opaque guard binds every check to the original context, transaction, scope and intent. Denial is sticky; copies, cancellation, expiry and closed transactions fail. Path checks admit at most 4096 actions and 1 MiB aggregate selector bytes. `Finalize` rechecks transaction binding, settings, catalog and conservative clock immediately before commit admission. It does not prove the physical WAL flush precedes expiry. Trusted composition must call `Close` on every terminal and error path; it releases bounded store admission but does not commit or roll back the caller's transaction. SQL fences persist until the caller ends that transaction.

This component is neither `PostgresIntentAuthorization` nor a publication, object delivery or retention grant. Complete native authorization must derive all actual operation, path, history, provenance and retained-generation requirements, including durable repository-to-signed-tenant uniqueness, before admitting publication or disclosure. A digest or scope is never bearer permission.
